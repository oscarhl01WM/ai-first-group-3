# A-M4-01: Coordinate consented user pilot sessions

**Status:** Draft for review and assignment
**Owner:** A — Frontend / Interface
**Milestone / priority:** M4 — pilot and release decision
**Related requirements:** End-to-end MVP journey; proposed pilot measures in MVP plan §3
**Collaborators:** B verifies price/source caveats; C reviews recipe/restriction cases; D coordinates operational readiness; all four review evidence.

## Description
Prepare and run pilot sessions with participant consent, using the integrated release candidate and the measures/targets the team explicitly adopts. Collect privacy-minimized observations about task completion, comprehension, time, and error recovery; report limitations and defects without assuming proposed targets are release gates.

## Acceptance criteria
- [ ] The team approves the session script, consent approach, data minimization, participant handling, and any adopted success measures before sessions.
- [ ] Sessions exercise normal, no-match, stale/missing-price, over-budget, and adjustment paths using permitted pilot data.
- [ ] Results include method, participant count, observed outcomes, limitations, and usability defects without unnecessary personal data.
- [ ] Critical usability issues are triaged with owners before the release decision.

## Dependencies
- M3 quality gates and source-permission evidence; D-M4-01 release readiness.
- Team approval of pilot targets and privacy handling; proposed targets are not presumed adopted.

## Open questions and constraints
- Recruitment, pilot size, consent process, and target thresholds require team approval.
- No real participant data should be collected until privacy and retention rules are agreed.
